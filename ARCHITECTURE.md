# Architecture

- **Presentation** uses Next.js App Router, React, TypeScript strict mode, Tailwind CSS and a shared CSS theme. The locale layout controls HTML language, navigation and footer. The localized route handler renders the public, customer and admin pages. Checkout and downloads have separate server boundaries.
- **Motion** uses a shared visibility hook and CSS timing to drive presentation examples. The hook observes viewport entry, document visibility and reduced-motion settings. Workflow timers are local simulation state and remain independent of saving, checkout and actual Office Scripts generation. The approved Pearl & Iris tokens apply to the public site, forms, workspace and light React Flow canvas.
- **Builder** uses React Flow for positioning, connections and navigation. The domain module validates a directed chain of supported Excel operations and compiles versioned Office Scripts. A deterministic synthetic preview models selected operations. It does not call Excel.
- **Application** uses server actions for authentication, workflow persistence, checkout, project requests, catalog updates and quotation revisions. Authentication resolves an opaque local session or a configured Supabase user. Admin authorization comes from server-owned account state.
- **Local infrastructure** uses Node.js SQLite with WAL, foreign keys, transactional updates and bounded application-level rate limits. Owner predicates protect customer workflow, order, request and download lookups. The database is available only in the local preview.
- **Commerce** stores a validated graph and price snapshot on order creation. Verified Stripe events or an explicit simulator action update the order. The paid order acts as the local entitlement. An authenticated download regenerates a versioned ZIP on demand and records the download.
- **Advisory** adds a bilingual consulting catalogue, a process model and a five-step browser diagnostic. The result is computed without a network request. An explicit submission sends the answers and contact details, and the server validates the fields and independently recomputes the versioned result. Consultation leads use the existing requests table with source `advisory` and share its transactional idempotency and rate limits. See [Advisory](ADVISORY.md) for the rules and lifecycle.
- **Advisory workspace** extends requests with project details, text deliverables, support requests and itemized quotation revisions. Customer reads derive ownership from the authenticated session. Internal notes, drafts and unapproved deliverables stay in the admin workspace. Local storage uses additive SQLite tables. The PostgreSQL migration defines separate RLS boundaries for a future Supabase repository.
- **Future infrastructure** has a PostgreSQL schema and RLS migration for a disposable Supabase environment. The runtime currently uses SQLite even when Supabase Auth is configured. PostgreSQL repositories, Storage delivery, hosted admin role provisioning, retention tooling and transactional email remain separate integration work.

The lockfile pins all dependencies. The app uses locally bundled OFL fonts carried forward from FluxClar, with their license files.
